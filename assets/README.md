# assets — 素材の収集（工程C）

**ライセンスが明示されている素材だけを集め、クレジットまで自動で組む。**

元チャンネルは概要欄で画像を全点クレジットしている（CC BY / CC BY-SA を作者名と
ライセンス名つきで列挙）。それを機械でやるため、収集の時点で作者とライセンスを
必ず持ち帰る。ライセンスが判定できない素材は捨てる。後から調べ直せないため。

```bash
python -m assets search "Antikythera mechanism"
python -m assets fetch seeds/shots/oparts.yaml --out video/public/shots
```

## カット仕様

```yaml
shots:
  # query は配列で言い換えを並べられる。上から順に試す
  - query: [Baghdad battery, Parthian battery, Khujut Rabu]
  - query: [Ottoman map, Ottoman portolan, Piri Reis Kitab]
```

タイトル一致で絞るため、言い換えを2〜3個書いておくと取りこぼしが減る。

## 収集元

| ソース | ライセンス | 備考 |
|---|---|---|
| Wikimedia Commons | APIで取得 | 作者・ライセンス・使用条件が全部返る。主力 |
| NASA Images | 原則PD | 宇宙・地球観測 |
| Met Museum | CC0のみ | 美術品。1点1リクエストなので遅い |

**CC BY-NC / CC BY-ND / Fair use は自動で落とす。** 動画に使えないため。

## 実測で踏んだ落とし穴

**1. キーワード検索は平気で無関係な画像を返す。**
`Baghdad battery` で**バグダッドの米兵の写真**が返ってきた。`Baghdad` だけ一致して
`battery` が無視されている。先頭語を必須にし、残りも半分は含ませる
`title_matches` を入れて弾いている。

**2. 拡張子が中身と食い違う。**
Commons は `.jpg` という名前で PNG や WebP を返す。マジックバイトから判定して
正しい拡張子で保存する。manifest に実ファイル名を記録している。

**3. 巨大なスキャン画像はサムネイルが取れず403になる。**
`thumburl` でも `Special:FilePath` でも同じ。URLの組み立て方では解決しないので、
候補を順に試して落とせたものを採る。

**4. 絞り込みを厳しくすると0件になる題材がある。**
黙って諦めるのでも、黙って無関係な画像を使うのでもなく、
先頭語だけの緩和検索に落として `needs_review` を立て、人の確認に回す。

**5. 読み込めても黒い画面になる素材がある。**
SVG由来の透明PNGは暗い背景の上で完全に消える。暗すぎる写真も同じ。
実測で、収集した7枚のうち2枚がこれだった（平均輝度 0 と 6）。
黒に合成してから平均輝度を測り、`MIN_MEAN_LUMA` 未満なら次の候補へ進む。

## 残る人の作業

- **画の適否は目で見る必要がある。** タイトル一致は明らかに違うものを弾くだけで、
  「その画がそのカットにふさわしいか」は判定していない
- `★要確認` が付いたカットは必ず見る
- 写真が存在しないもの（再現映像・図解）は別途生成する

## 検証

`tests/test_assets.py` — 米兵の写真を弾く回帰テスト、ライセンス判定、
拡張子のマジックバイト判定、クレジット生成、緩和モードの意味論。

緩和モードのテストが実バグを1件検出した。`min_ratio=0` を渡しても
`max(1, ...)` が1語必須を強制しており、緩和が機能していなかった。
