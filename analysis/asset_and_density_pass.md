# 素材と密度の詰め（実測）

参考chと同じ粒度の動画を台本から作れるようにするための一巡。
判断はすべて、描画したフレームを見るか、propsを数えるかで確かめている。

## 結果

| | 前 | 後 | 参考ch |
|---|---|---|---|
| 異なる画像 | 7枚 | **24枚** | — |
| 1枚あたりの使い回し | 16.0回 | **4.7回** | — |
| オーバーレイ被覆率 | 42.4% | **67.0%** | 67.0% |
| 語りと画の一致 | 検索一致（誤りあり） | **記事由来** | — |

被覆率は `analysis/reference_edit_density.md` の実測値（324フレーム、閾値0.10）と
同じ定義で比べている。字幕と出典帯は両方とも除外した。

## 1. 画は検索ではなく記事から引く

キーワード検索は語義を区別しない。実測で返ってきたもの:

| 検索語 | 返ってきた画 |
|---|---|
| Archimedes | 月のアルキメデス・クレーター（NASA） |
| Columbus | ジョージア州コロンバス市の観光写真 |
| Baghdad | 1258年のバグダード陥落図 |
| Out-of-place artifact | 芝生に置かれた掃除機（Flickrの同名写真） |

言語間リンクで英語版の記事を特定できている以上、その記事に載っている画像を
取ればよい。記事の同一性が固定されているので、同名衝突が原理的に起きない。
`en.wikipedia.org/wiki/Archimedes` に載っている画は、定義上アルキメデス本人のものになる。

検索は、記事に画が1枚も無い題材だけの退避路に下げた。その場合は manifest に
`needs_review` を立てて人の確認に回す。

記事の体裁として貼られている画（Commons-logo、保護の錠、注意書きの天秤、
秀逸記事の星）は名前で落とす。実測で Baghdad Battery の記事から
中立性の注意アイコンが素材として通っていた。

## 2. 検索語の選び方

**個体とクラスを分ける。** Wikidata では個体は P31（instance of）を持ち、
クラスは P279（subclass of）を持つ。Washer (hardware) や Volcanic rock は
P279 しか持たない。単位や記法（Percentage = parts-per notation）は P31 を
持ってしまうので、型のラベルで別に落とす。

語を列挙して弾く運用は題材が変わるたびに漏れた
（Channel → Primary source → Metre → Percentage → Washer (hardware) の順に漏れた）。

**器は採らない。** 掲載誌・所蔵館・発見地の国は、題材が言及される器であって
題材ではない。記事の画像は器の画像（雑誌の表紙、建物、地図）になる。
台本の本文では主題が代名詞で受けられ、名前は主張の頭にしか出ないので、
器を採るとその区間だけ主題から離れた画に差し替わる。実測で本文の途中に
ネイチャー誌の表紙が全画面で出た。語が無い区間として扱い、前の主題を引き継がせる。

**固有性で選ぶ。** 長い語から試すと、どの区間にも出る背景語が各区間を占める。
実測で「紀元前」が Ante Christum natum として全42区間に配られた。

## 3. 密度は67%で止める

データ由来の部品は、台本に根拠となる値がある所にしか出せない。そこだけ埋めた
結果、被覆率は42.4%で頭打ちになった。差の25ポイントを埋めているのは、
参考動画では語りの語句そのものの大字だった。

出す語句は**行の連続部分文字列に限る**。言い換えたり要約したりすると音声と
食い違う余地ができるが、逐語なら少なくとも矛盾はしない。密度を上げる手段のうち、
精度を落とさずに済むのはこれだけ。

埋めきらずに67%で止める。参考動画では9%のフレームに何も載っていなかった。
100%まで埋めると、密度を合わせたつもりで密度の方が外れる（実測で92.8%まで行った）。

## 4. 画面に出る断定を止める

描画して初めて見つかった誤り。いずれも「台本より強いことを画面が言う」型。

| 台本 | 出ていた表示 | 直した後 |
|---|---|---|
| 歯車は30個以上 | 30個 | 30個以上 |
| 2000字を超える | 2000字 | 2000字を超える |
| 水深40メートルを超える | 40メートル | 40メートルを超える |
| 20枚あまり | 20枚 | 20枚あまり |
| 比較的新しい | 比較的新（大字） | 出さない |

見出しも文をそのまま切っていたため、文の途中から始まって助詞で終わる断片に
なっていた（「だから手元の20枚あまりを」）。文頭の接続を外し、数値の直後で切り、
末尾の助詞を落とす。

語句テロップは台本全体での出現回数が少ない語を選ぶ。長さだけで選ぶと
どの行にも出る一般語が大書きされた（「観光客」）。

## 5. 画面の作り

- **ピラーボックス**は素材の実寸で決める。素材24枚のうち約半分が縦長で、
  16:9に cover で敷くと肖像画の顔や写本の欄外が切れる。4:3は切っても
  写真なら破綻しないので、境目は正方形の手前（縦横比1.2）に置いた。
- 空いた左右は**同じ画をぼかして敷いて**埋める。黒帯のままだと縦長の素材が
  続く区間で画面が細長い窓のようになる。
- **出典表示は画面に出ている画のものを出す**。並び順で突き合わせていたため、
  CC BY の画に別人の名前が付いていた。表示義務のあるライセンスでそれをやると、
  表示していないのと変わらない。

## 6. 処理時間

英訳と個体判定を1語ずつ引いていたため、台本1本で数百往復になり、レート制限の
待ちで1時間を超えていた。どちらもAPIが50件まとめて受けるので、語の数ではなく
バッチ数で効く形にした。**同じ処理が1分以内**に収まる。

まとめて引けるようになったので、「上位から試して打ち切る」もやめた。打ち切りは、
記事の無い複合語が候補の上位を埋めたときに、その下にある使える語まで
諦めていた（取得できた区間が17から7に落ちた）。

## 残っている弱点

- **語が取れる区間が13/67**。台本の本文は主題を代名詞で受けるので、名前が
  書かれた区間でしか語が起きない。残りは前の主題を引き継いでいる。
  引き継ぎ先は正しい題材だが、1つの記事の画を回して使うことになる。
- **人物の画が弱い**。ヴァレリオス・スタイスのように記事に画像が無い人物は、
  検索に落ちても拾えない。冒頭10区間がこれに当たり、最初に取れた画を
  遡って当てている。
- **ナレーション音声が無い**。字幕の時刻は文字数から割っているので、
  TTSを入れた後に実際の発話へ合わせ直す必要がある。
