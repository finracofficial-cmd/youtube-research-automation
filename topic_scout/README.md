# topic_scout — 題材選定（工程A）

分析で出た勝ち条件 **「需要が実証済み × 供給が低品質 × 時流ワード」** を実装したスコアラー。
YouTube 検索結果から題材の当たりやすさを採点してランキングする。

```bash
# 1) 量産系チャンネルから題材候補を自動発掘（手書きシード不要）
python -m topic_scout discover --out out/candidates.csv

# 2) 候補を採点してランキング
python -m topic_scout scout --seeds out/candidates.csv --exclude <自チャンネルのchannel_id>

# 3) 気になった1件の内訳を見る
python -m topic_scout explain "ダイアトロフ峠事件"
```

毎回1〜3を回せば、人が題材を思いつく必要がなくなる。

## なぜこの工程が最優先か

3本の実測では、**制作フォーマットが同一なのに再生数が100倍違った**。
しかも最も高評価率が高い（＝満足度が高い）のは再生数が最下位の回だった。
脚本と編集をいくら自動化しても、ここを外すと1.2万再生になる。

## 題材プールをどう設計するか

**ジャンルで広げる／絞るのではなく、「裁定が効く条件」で絞る。**

採点結果が示したこと:

| 帯 | 需要 | 空白 | 例 | 判定 |
|---|---|---|---|---|
| 科学の未解決 | あり | **ゼロ** | リーマン予想・暗黒物質・球電 | まともな科学chが既に押さえている |
| マイナーな未解読文字 | **ゼロ** | あり | ロンゴロンゴ・線文字A・エトルリア語 | 空白1.00でも誰も検索しない |
| 有名すぎる謎 | あり | **ゼロ** | ギザの大ピラミッド | 真面目な長尺が8本 |
| **都市伝説として消費されている中堅の謎** | **あり** | **あり** | ヴォイニッチ手稿・ダイアトロフ峠事件 | **ここだけ成立する** |

つまりチャンネルの堀は「未解決の謎」というジャンルではなく、
**「都市伝説的に語られている量」と「実在する一次資料の量」の乖離**そのもの。
供給が丸ごとゆっくり／オカルトに占領されている帯にしか裁定は残っていない。

「ヴォイニッチが当たったから次も未解読文書」は直感的だが、データ上は誤り。
当たったのは"未解読文書"というジャンルではなく、**ヴォイニッチ手稿という固有名詞が持っていた検索需要**。

### 幅は自動発掘で稼ぐ（discover.py）

手書きシードは書いた人間の思いつきに偏り、スケールしない。
代わりに**量産系チャンネル自体を需要センサーとして使う**。
彼らは再生が取れる題材を毎週出し続けているので、その題材名を吸い上げれば
需要が実証済みの候補プールになる。

1. `scout` の検索結果から量産系チャンネルを特定（23題材の走査で178ch見つかった）
2. 上位28chの直近60本のタイトルを取得（1,559本）
3. カタカナ語・漢字複合・「〜事件/手稿/遺跡」パターンで題材名を抽出（1,335語）
4. **複数チャンネルが扱っている語**ほど需要が実証されている → 3ch以上で48語に絞る
5. その48語を `scout` に流す

チャンネルタブでは再生数が取れない（NA）ため、発掘段階の需要代理は
「何チャンネルが扱ったか」。実際の需要は後段の `score.py` が測る。

## 一次資料の厚みをスコアに入れていない理由

このフォーマットは概要欄に15〜30本の出典を並べる。資料が無い題材では成立しないので、
当初 Crossref で「一次資料の厚み」を4つ目の軸にしようとしたが、**やめた**:

- あいまい検索で `Antikythera mechanism` が707,615件（"mechanism"が全部に当たる）
- タイトル一致で絞っても `Dead Sea Scrolls` の2015年以降が0件になるなど不安定
- **英語圏偏重**。神代文字・与那国島海底地形のような日本語題材は誤ってゼロになる

ノイズの多い指標を掛け算に入れると判断が歪む。
資料の有無はショートリスト（月3〜5件）に絞ってから人が見るほうが速くて正確。

## スコアの構造

```
score = sqrt(需要 D × 空白 G) × 時流 T
```

**加算ではなく乗算**にしている。実測で、2本の失敗がそれぞれ別の理由で死んでいるため：

| | D | G | 結果 |
|---|---|---|---|
| カエサルの最後の息（橋本環奈回） | **0.00** | 0.07 | 1.2万 — 誰も検索していない |
| ギザの大ピラミッド | 0.99 | **0.00** | 3.3万 — 真面目な長尺が既に8本ある |
| ヴォイニッチ手稿 | 0.95 | 1.00 | **133万** |

どちらか一方がゼロなら題材として死ぬ。幾何平均はこれを表現する。

### D（需要）
`上位25%の再生数` と `10万再生を超えたチャンネルの数` の加重和。
後者が重要で、**複数の別チャンネルが当てている題材ほど、チャンネル力ではなく題材の引力**である可能性が高い。
1本だけ突出しているケースを需要と誤認しないための設計。

### G（空白）
`量産・煽り系の比率` から、既存の真面目な長尺による飽和を引く。
飽和は**本数を主、最高到達点を従**で測る。ヴォイニッチ手稿には62万再生の良質番組（ガリレオX）が
既にあったが、それでも133万を取れた。**1本の成功作は題材を占有しない。**
一方ピラミッドは真面目な長尺が8本並んでおり、埋まっている。

### T（時流）
現状は AI 切り口が既に使われ機能しているかを見る。
**下限0.6を持つ増幅器**であってゲートではない。3本の実測に「T を外して失敗した例」が無く、
「T がゼロなら死ぬ」証拠が無いため、掛け算で殺さない設計にしている。

## 分類（classify.py）

供給の質を切り分ける。`is_low_effort` に落ちるのは:
- **ゆっくり・合成音声系**: ゆっくり / 霊夢 / 魔理沙 / ずんだもん / VOICEVOX
- **オカルト煽り**: 都市伝説 / 衝撃 / ヤバ / 禁断 / 震撼
- **総集編・睡眠用**: 題材そのものの競合ではないため除外対象
- **「解決したと言い張る」系**: `ついに解読` / `解読成功` / `暴いた` / `判明した` / `正体`
  → 未解決のはずの謎を「解いた」と言うのは煽り側の言い方。真面目な解説はこの語彙を使わない

`is_serious_longform` = 25分以上 かつ 上記フラグがどれも立たない = 直接競合。

## 検証

`python3 validate.py` で既知3本の逆算検証が走る（自チャンネルの動画は競合から除外して採点）。

```
題材                     実績再生   実際   判定    score    D     G     T
ヴォイニッチ手稿        1,329,050   hit   狙う    0.764  0.95  1.00  0.78
ギザの大ピラミッド 謎       33,028   miss  見送り  0.000  0.99  0.00  0.60
カエサルの最後の息 分子      12,597   miss  見送り  0.000  0.00  0.07  0.60
```

3本とも順序・判定ともに一致し、**2つの失敗は別々の理由で落ちている**（需要欠如 / 空白欠如）。

### 閾値感度
`SERIOUS_MIN_DURATION` を変えても判定は安定している:

| 閾値 | ヴォイニッチ | ピラミッド | カエサル |
|---|---|---|---|
| 15分 | 狙う 0.68 | 見送り 0.00 | 見送り 0.00 |
| 20分 | 狙う 0.68 | 見送り 0.00 | 見送り 0.00 |
| **25分** | **狙う 0.76** | **見送り 0.00** | **見送り 0.00** |
| 30分 | 狙う 0.76 | 条件付き 0.33 | 見送り 0.00 |

30分以上にするとピラミッドを取りこぼす。25分を採用している。

## 発掘の既知の限界

- **発掘は元の検索のバイアスを引き継ぐ**。供給側チャンネルは `scout` の検索結果から特定するため、
  最初に投げた題材が古代文明寄りだと、発掘される候補も古代文明寄りになる。
  実際、今回の43候補にダイアトロフ峠事件（未解決事件系）は入っていない。
  **毛色の違う題材を最初のシードに数件混ぜてから discover を回すこと**
- **一般名詞が混じる**。「オーパーツ」「ロストテクノロジー」は題材として成立するが、
  同じ経路で「設計図」「巨大都市」のような一般名詞も出る。形態素レベルのフィルタで
  切れ端（`再現不`, `超高`）は落とせるが、一般名詞は完全には落とせない。
  最終的に残るのは十数件なので、人が2分眺めて捨てる前提の設計にしている

## 既知の限界

- **キャリブレーションは実質3点**。過学習していないとは言い切れない。新規題材を出す度に実績を
  `seeds/candidates.yaml` の validation に追加して再検証すること
- **投稿日が取れない**。`--flat-playlist` は upload_date を返さないため、「需要が今あるのか、
  5年前のものか」を区別できていない。T が弱いのはこれが理由。Data API v3 を使えば解消する
- **登録者数が取れない**。`distinct_channels_over_100k` で代用している
- 検索結果は実行した IP / ロケールに YouTube が返したスナップショット。再現性は完全ではない
- `lang=ja` は必須。付けないとタイトルが自動翻訳され、「ゆっくり解説」が
  "A slow explanation" になって分類が丸ごと壊れる（実際に一度壊れた）
