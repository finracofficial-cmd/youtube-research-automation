# script_engine — 台本の骨組みと、見続けさせる装置

元チャンネル2本（ヴォイニッチ回52:39 / ピラミッド回37:52）の構造と文体を計測し、
**題材非依存の骨**として抜き出したもの。題材を差し替えても同じ構造の台本が出る。

```bash
# 調査 → 台本プロンプト（資料入り）
python -m research pipeline seeds/topics/voynich-manuscript.yaml --duration 900 --out out/prompt_voynich.txt

# 設計図モードで書く（章ごとの仕掛けを先に決めてから、塊ごとに書く）
python -m script_engine write out/prompt_voynich.txt --spec seeds/topics/voynich-manuscript.yaml \
  --out drafts/voynich-manuscript.txt --duration 900

# 書き上がった台本を実測プロファイルと装置のレンジに照らす
python -m script_engine check drafts/voynich-manuscript.txt --duration 900 --subject ヴォイニッチ手稿
```

## 2段で書く理由（2026-09-24）

一気に書かせた台本は `check` に合格していたのに平板だった。参考2本の本文と
並べて数えると、無いものがはっきりした（`analysis/retention_devices.md`）。

| 装置 | 参考（/分） | うちの台本 |
|---|---|---|
| 語り手の判断（私は判断を保留する） | 0.03〜0.13 | **0** |
| 留保（ただし） | 0.19〜0.53 | 0 |
| 文頭の反転（だが・しかし） | 0.26〜0.53 | **1.40** |
| 伏線→回収（1章で開いて最終章で拾う） | 有 | 無 |
| 章頭で結論を先に言う | 6/9章 | 0/5章 |

反転だけ参考の2.6倍。振り子ではなく否定の連打になっていた。字数を要求されて
事実が足りないと「1点目が1404年。2点目が1438年」と列挙で埋める。

```
plan.py     設計図。章ごとに 結論／なぜ／出どころ／振り子（肯定→反転→留保）／
            証拠／数字と断り／専門語の着地／語り手の判断／結論の範囲／次への引き。
            伏線を開く章と、題材より大きい主題もここで決める。JSONで受け、形が崩れて
            いれば1回だけ書き直させる
compose.py  塊ごとに書く（冒頭 4.0% / 章 / 着地 11.5%）。監査の指摘は装置の
            住んでいる塊へ配り（伏線→冒頭、回収→着地、率の不足→章）、その塊だけ直す
devices.py  監査。上の表のレンジと、伏線・回収・章末の引き・水増しを見る。
            tests/test_devices.py が参考2本を自身の監査に通している
```

語り手は**判断だけ**書く。「私は全部読んだ」は生成では捏造になるので、
`plan.validate` が行為の形を落とす。

## 安定させる仕組み（2026-09-24）

同じ資料で6本書かせたら、語り手の判断 0.00〜0.27/分、結論先出し 2/5〜5/5、
資料に無い数字 2〜7件と揺れた。1本ずつでは揺れが設定のせいか偶然かも分からない。

```bash
# 同じ資料で3本書かせ、指標ごとに平均・最小・最大・幅を出す（幅20%以上は不安定）
python -m script_engine bench out/prompt_x.txt --spec seeds/topics/x.yaml --runs 3 \
  --out analysis/bench/<日付>/x.json
```

揺れを減らす側は3つ。どれも「作って選ぶ」か「番号で縛る」で、文章の巧さには触らない。

| 仕組み | 何をするか | 既定 |
|---|---|---|
| 設計図の選択 | 設計図を `--plans` 本作り、資料への沿い方（出どころ・残った数字・判断・具体の画）の点で選ぶ | 2 |
| 塊の選択 | 塊ごとに `--candidates` 本作り、装置の点（結論先出し・引き・出どころ・振り子・水増し・資料に無い数字・字数）で選ぶ | 2 |
| 根拠番号 | 資料を番号付きで章に渡し、数字の文に〔n〕を付けさせる。番号の無い数字の文は消させ、採るときに剥がす | 有効 |

### トークンの節約（2026-09-24）

候補選択の初回設定は1本 27回・14.6万トークンだった（旧 19回・5.8万）。無駄が3つあった。

| 無駄 | 直し方 |
|---|---|
| 番号付き資料（約4,000トークン）を章の呼び出しごとに全部送っていた | 章の指示との重なりで上位14行＋題材の記述だけ。番号は通しのまま |
| 率の指摘（ただしが少ない等）で全章を書き直していた | 率は書き直しても揃わない（bench 実測）。嘘・構造・水増し・文長だけを引き金にする |
| 候補を常に2本作っていた | 1本目の点が閾値（章4点・冒頭5点）未満のときだけ2本目 |

構造の安定は機械的保証（`ensure_*`）が担っていて、これはトークンを使わない。
既定は `--plans 1 --candidates 2 --rounds 1`。

書き手が落としがちな装置は、書かせたあとに機械的に置く（`compose.ensure_plant` /
`ensure_verdict` / `ensure_callback`）。設計図には毎回あるのに、bench では3本中1本が
回収を、3本とも半数の章で結論先出しを落とした。設計図の文は形の検査を通っているので、
無ければそのまま入れる。伏線は出発の合図の前、結論は「そう語られている」の直後、
回収は最終章の頭（参考と同じ位置）。

安定性の実測は `analysis/bench/2026-09-24/README.md`。構造（引き・伏線・回収・字数・
文長・水増し無し）は安定した。率（語り手・留保・逆接）は参考自身も2本で2〜3倍違うので、
門にはせず指摘に留める。

書き上がりは**合格条件**で門を閉める（`reports/<name>_report.txt` に残る。設計図は
`reports/<name>_plan.json`）。**drafts/ には台本だけを置く。** 判定を台本の隣に置いたら
Make video に判定を渡されて、それを読み上げる動画ができた（#5）。make.py と Make video の
冒頭で `script_engine.guard` が台本でないファイルを弾く。
率の不足は指摘に留め、門にするのは「嘘をつく」「途中で離脱される」に直結するものだけ。

```
○ 資料に無い数字が無い
○ 伏線と回収がある
○ 全章が引きで終わる
○ 半数以上の章が結論を先に言う
○ 水増しが無い
○ 文体が参考のレンジ内
```

**尺は埋めない。** 字数は上限で、事実が尽きたら章を終える。資料が薄ければ台本は
短く出て、「この資料で書けた尺は約N分」と言う。足りないのは文章ではなく調査。

## 設計方針

**「何を書くか」だけをLLMに委ね、「どう書くか」はコードで固定する。**
自由に書かせると必ず型から外れるため、構造・尺配分・文体はプロンプト側で決め打ちにし、
出来上がりを `check` で機械的に検証する。

## 2つの型

| | 旗艦型 | 束ね型 |
|---|---|---|
| 原型 | ヴォイニッチ回 | ピラミッド回 |
| 単位 | 単一題材の深掘り | N個の主張を1つずつ検証 |
| 標準尺 | 52:39 | 37:52 |
| 構成 | 4幕の時系列 | 主張ごとの章立て |

### 旗艦型の幕比（実測）
```
第1幕 19.8% → 第2幕 22.2% → 第3幕 25.2% → 第4幕 30.1%
```
**幕は後半ほど長い。** 意図的な逓増で、終盤に向けて密度を上げている。

### 束ね型の順序規則
主張は**信頼度の順**に並べる:
`当たっていたもの → 当たっているが理由が違うもの → 一次資料で跡形もなくなるもの`

先に視聴者の信念を肯定してから反転させる。最初から否定すると都市伝説層が離脱する。

## 共通ビート

| ビート | 比率 | 役割 |
|---|---|---|
| 体言止めの一撃 | 0.4% | 1秒目から本題。挨拶・自己紹介なし |
| 異様さの具体3つ | 1.0% | 画で示せる具体を3つ。形容詞でなく事実 |
| **チャンネル宣言** | 0.4% | ほぼ固定文。競合の語彙を否定する形で名乗る |
| 謎の核 | 0.7% | 「単に難しいからではない」型で凡庸な説明を先に潰す |
| 全体の地図 / 検証順の宣言 | 1.2% | 何幕あるか先に全部見せる＝長尺を見せる約束 |
| **出発の合図** | 0.3% | ほぼ固定文。「それでは私と共に、〜へと迫っていこう」 |
| 本編 | 約85% | 幕 or 主張 |
| 一般化 | 5.5% | 題材を離れた普遍的洞察。**ここが拡散の動力** |
| 回収 | 2.5% | 「〜と分かった」を反復し「だが〜は分かっていない」で落とす |
| 条件の提示 | 2.0% | いつ解決するかを願望でなく条件で答える |
| CTA | 1.5% | **ここだけ敬体**。語り手から人間に戻る |

本編内の規則:
- 幕・章の**最後の1文が次の問いになる**（オープンループ連鎖）
- 4〜5分に1回「ここまでが〜の話である。では〜はどうなのか」で締め直す
- 序盤で開いたループを終盤で回収する（ピラミッド回は1章で開いて9章で回収＝30分越し）

禁止:

必須:
- 断定できない箇所は「ただし」で留保（ピラミッド回で24回）
- 専門語は日常の比喩に着地（例: エントロピー → スマホの予測変換）

## 実際に1本通したときの記録（drafts/oparts_v1.txt）

題材「オーパーツ」束ね型5主張・15分で試した。

| 回 | 結果 | 内容 |
|---|---|---|
| 初稿 | **不合格** | 話速262字/分（下限320）。900秒に対し3,932字で約1,100字不足 |
| 加筆後 | 合格 / 忠実度88% | 数字密度が参照の71.7%しかない |
| 数字を足す | 合格 / **忠実度90%** | 数字密度81.9%まで回復 |

### ここで分かったこと

**「レンジを通る」と「型に忠実」は別物だった。**
初稿を加筆して validate は通ったが、数字密度は参照動画の72%しかなかった。
レンジが広いので端に張り付いたまま合格してしまう。
そこで `fidelity`（参照動画への近さ）を足し、`check` が両方を出すようにした。

**数字密度の不足は、文体の問題ではなく調査不足の症状である。**
記憶だけで書くと具体的な年・寸法・件数が出せず、ここが必ず落ちる。
逆に言えば `numerics_per_min` は「本当に一次資料に当たったか」の代理指標として機能する。
81.9%で頭打ちになったのは、一次資料を手元に置かずに書いたからで、
文章を直して埋まる種類の差ではない。

### 運用上の注意

`check` が通ることは**文体と構造の保証であって、事実の保証ではない**。
出典の当たり込みと事実確認は人間の工程として必ず残る。

## 別テーマでも同じ構成になるか（実測 n=3）

オーパーツ（束ね型15分）、巨石遺跡（束ね型15分）、ナスカの地上絵（**旗艦型20分**）で比較。

```
指標                      参照   オーパーツ     巨石遺跡      ナスカ
avg_sentence_len        21.30  19.83( 93%) 20.66( 97%) 19.87( 93%)
sentences_per_min       16.60  17.20(104%) 15.60( 94%) 16.15( 97%)
chars_per_min          354.00 341.07( 96%) 322.27( 91%) 320.85( 91%)
numerics_per_min         7.90   6.47( 82%)  7.93(100%)  5.95( 75%)
short_sentence_ratio     0.14   0.12( 83%)  0.11( 76%)  0.15(111%)
忠実度                   100%         90%         92%         89%
```

3本とも `check` に合格する。忠実度も89〜92%で揃う。

### だが「安定」ではない

```
テーマ間のばらつき
  avg_sentence_len      幅  3.9%   ← 骨格
  sentences_per_min     幅  9.6%   ← 骨格
  chars_per_min         幅  5.7%   ← 骨格
  numerics_per_min      幅 25.1%   ← 肌理
  short_sentence_ratio  幅 34.3%   ← 肌理

最大ぶれ 34.3% → 不安定（20%未満を安定とみなす）
```

**骨格は再現するが、肌理は再現しない。** これがn=3で分かったこと。
n=2（束ね型だけ）では18.6%で「安定」に見えたが、旗艦型を入れると倍近くに開いた。

### 数字密度は、書き手の腕ではなく調査の歩留まりで決まる

| 台本 | 調査で取れた数字入り記述 | numerics_per_min |
|---|---|---|
| 巨石遺跡 | 8件 | **100%** |
| オーパーツ | 0件 | 82% |
| ナスカ | 0件（第4幕は出典0件） | **75%** |

きれいに対応している。**文章を直しても埋まらない。調査を厚くするしかない。**

### 初稿は必ず薄い。しかも長尺ほど薄い

| | 初稿の話速 | 目標比 | 合格までの加筆回数 |
|---|---|---|---|
| オーパーツ 15分 | 262字/分 | 0.72 | 2回 |
| 巨石遺跡 15分 | 253字/分 | 0.69 | 2回 |
| **ナスカ 20分** | **225字/分** | **0.63** | **4回** |

`DRAFT_INFLATION = 1.4` でも旗艦型には足りない。尺が伸びるほど不足率が上がる。

### この比較で言えること／言えないこと

**言えること**: 骨格（構成・尺配分・文長・話速）は題材と形式を変えても再現する。ぶれは10%以下。

**言えないこと**:
- 肌理（数字密度・短文のリズム）は再現しない。ぶれ25〜34%
- n=3、すべて同じ書き手
- **構造が同じでも、当たるかどうかは別問題。**
  元チャンネル自身が証拠になっている。ヴォイニッチ回とピラミッド回は
  同じ書き手・同じ型・同じ章構成で、ピラミッド回のほうが出典は多い（32本対16本）。
  結果は133万対3.3万、**40倍の差**。
  ここで保証しているのは「型から外れないこと」であって、成果ではない
